# 快速录入：剪贴板跟随录入

状态：已实现。适用于 Windows 桌面版。

目标：在其他软件复制一项信息后，自动写入快速录入当前记录的指定字段，按用户配置的顺序前进；复制过程中继续操作信息来源软件。

## 用户流程

1. 打开“快捷表头与尺寸”，分别设置快速录入表头顺序和剪贴板粘贴顺序。可拖动排序，拖到列表顶部或底部会直接移到最前或最后，靠近边缘会自动滚动；也可使用移到最前、上移、下移、移到最后按钮。设置按项目保存，粘贴顺序与表单显示顺序独立；病理号和蜡块号不参与自动填入。
2. 开启“剪贴板跟随”。该功能默认关闭，浏览器模式及非 Windows 环境中不可开启。
3. 新增记录页不显示也不启动剪贴板跟随。输入“病理号-蜡块号”并按 Enter 后创建记录、清空输入框，继续新增下一条。需要为已有记录补录信息时，从左侧病理号列表进入修改页。
4. 在已有记录的修改页点“确认本条并开始”。状态栏显示当前病理号、蜡块号及“当前项：姓名（1/5）”。进入其他软件，复制姓名后自动填姓名，当前项变为性别；下一次复制再填性别，依此类推。当前字段和刚填入的字段会高亮。
5. 每次填入只更新表单草稿和进度。全部字段完成后停止接收，Ctrl+Enter 沿用现有批量预校验/保存流程；保存失败保留表单和错误提示。
6. 保存后进入下一条记录时，程序把下一条病理号写入剪贴板，并提示“已进入下一条记录，病理号 … 已写入剪贴板”。默认等待确认，按 Enter 或点“确认本条并开始”再接收。设置中可勾选“保存进入下一条后自动开始接收”；仍需开启“修改后自动进入下一条”。

修改表单提供“暂停/继续”“粘贴”“跳过当前项”“撤回至上一项”“重新开始录入”。“粘贴”会主动读取当前剪贴板并填入当前项，即使内容从上次复制后没有变化也可以使用。自动填入只更新值和高亮，不调用窗口激活或抢走外部软件的键盘焦点。

## 状态和边界

| 状态 | 接收剪贴板 | 下一步 |
|---|---|---|
| 未开启 / 等待确认 | 不填业务字段 | 在已有记录修改页确认本条 |
| 接收中 | 写入当前字段，成功后前进一项 | 最后一项完成后停止 |
| 暂停 / 字段校验失败 | 不前进、不消费新值 | 修正、跳过或继续 |
| 本条完成 / 保存中 | 停止填入 | 保存成功后等待下一条确认 |

每个事件绑定会话 ID、项目 ID、记录 ID、事件编号和剪贴板序列号，表单根据本会话的当前步骤选择字段。切换项目、记录、重置或关闭窗口立即使旧会话失效，迟到的事件不能写入新记录。只有当前可编辑记录可以开启接收；记录锁定、已生成报告、标识尚未保存、字段配置发生变化时停止接收并提示。

开始接收时记录当前剪贴板序列号，忽略已有内容。每次系统更新按序列号去重，而不按文字内容去重，允许两个字段连续填入相同文本。点击“继续接收”后需要重新复制；如需使用已有剪贴板内容，可点“粘贴”。

空内容、图片和文件列表不推进顺序。日期、数字和选项字段先规范化/校验；校验失败停在当前字段。文本超过 32,768 个字符时暂停，不填入该内容。

非空字段默认受保护：新值与原值不同时暂停，由用户点“覆盖当前项”或“跳过当前项”；设置中可允许自动覆盖。“撤回至上一项”恢复自动填入前的值并暂停；如果用户随后手动修改了该字段，撤回会保留手动修改。连续事件串行处理；遇到未处理的校验错误暂停，避免后续信息错位。

监听依据剪贴板变化，不监听普通按键。Ctrl+A 只会全选，不影响跟随；Ctrl+C 和 Ctrl+X 会改变剪贴板，因此会按当前顺序填入。在快速录入页且存在自动填入历史时，焦点不在输入框内按一次 Ctrl+Z 就执行“撤回至上一项”；焦点在输入框内时，第一次 Ctrl+Z 保留给输入框自身撤销，同一输入框内再次按 Ctrl+Z 才执行“撤回至上一项”。切换输入框或继续输入其他内容后重新计数。

窗口隐藏、最小化、刷新、关闭，或打开字段设置、开始保存时停止当前接收。普通失焦不会停止，外部软件仍可保持前台。小窗口下状态栏和表单共同滚动，操作按钮可横向滚动，底部保存按钮保持可见。

## 实现结构

- **Windows 事件层**：`backend/app/services/clipboard_listener.py` 使用 `AddClipboardFormatListener` 接收 `WM_CLIPBOARDUPDATE`，读取 Unicode 文本、序列号及内部来源标记。通过现有后端可执行文件的 `--clipboard-listener` 独立模式运行，不启动 HTTP 服务或打开业务数据库；没有活动会话时不读取剪贴板。stdin 接收命令，stdout 仅输出 JSON 协议，不额外保存剪贴板历史或输出文本日志。无控制台启动时从 Windows 标准句柄恢复管道流。
- **Electron 主进程**：`frontend/electron/clipboard-follow.cjs` 管理 helper 的启动/停止、请求超时及会话，`main.cjs` 校验 IPC 来源。只允许快速录入窗口控制监听，事件仅发往该窗口；隐藏、最小化、重载使会话失效，关闭、renderer 异常退出或应用退出时结束监听子进程。主进程统一管理，外部软件前台复制不依赖 renderer 定时轮询或浏览器剪贴板读取权限。
- **preload / 类型定义**：提供开始、停止、主动接收当前剪贴板和接收事件的桥接方法，保持 `contextIsolation` 和已有 sender 校验。
- **QuickEntryView.vue**：状态条、独立排序设置和记录确认负责交互；绑定记录前不接收，自动填入只改表单草稿，保存仍走 `previewCellBatch → commitCellBatch`。
- **quickEntry.ts / clipboardFollow.ts**：配置迁移到版本 5，保留原有字体、尺寸、选中字段和固定字段。旧配置默认关闭跟随，顺序从已选字段中排除记录标识后取得；状态工具负责事件校验、当前步骤、保护原值、跳过和撤回。

保存后自动复制下一条病理号时，`copyPathologyNumber()` 经原生服务写入，并添加 `GeneLabLedger.InternalClipboard` 自定义格式标记。监听忽略带有该标记的内容，避免将下一条病理号误填为第一个业务字段；来源识别不依赖文字相等或时间间隔。非跟随桌面环境保留现有手动复制流程。

新增记录始终沿用连续创建流程，创建成功后清空新建框，不进入修改页，也不启动剪贴板监听。

## 参考案例与证据

- [CopyQ Scripting API](https://copyq.readthedocs.io/en/stable/scripting-api.html)：提供剪贴板变化回调和自动命令，并区分外部变化与自身写入。可借鉴事件处理和自触发过滤。
- [ClipboardFusion 触发器帮助](https://www.clipboardfusion.com/HelpGuide/TriggersAndMacros/)：提供 Clipboard Changed 触发条件，以及可拖拽排序的动作规则。可借鉴条件过滤与顺序配置。这些产品没有直接提供本项目的病理号绑定和字段游标。
- [Electron clipboard API](https://www.electronjs.org/docs/latest/api/clipboard)：提供剪贴板读写，未提供本功能所需的系统变化订阅。具体调用类型以项目安装的 Electron 版本为准，本实现使用原生监听服务接收变化事件。
- [Windows 剪贴板监听](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener)和[序列号 API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber)：支持系统变化通知和按更新识别事件。序列号递增表示剪贴板变化或清空，并不是对 Ctrl+C 键本身的监听。
