# 基因检测台账管理系统 — 产品需求文档

## 1. 产品定位

Gene Lab Ledger 是面向基因检测实验室的 Windows 单机台账工具，用统一数据库替代分散 Excel，同时保留实验室需要的 Excel 交换、编号编排、报告直接打印和定时归档能力。

目标用户包括实验室管理员、实验员、报告打印人员和质量负责人。当前不包含登录权限、多人实时协作、云同步、移动端或第三方 LIMS 对接。

## 2. 产品目标

- **记录清晰**：每条台账记录拥有独立 UUID，病理号可重复且不会隐式联动。
- **编排简单**：实验编排只做“选择记录 → 排序 → 生成并回写编号 → 导出”。
- **文件可控**：手动导出使用 Windows“另存为”；自动任务使用预设目录自动执行。
- **交换安全**：导出文件可回导，UUID 精确定位，预览后原子提交。
- **操作可追溯**：编辑、编排、导入、批删、打印和自动导出都记录审计。
- **桌面体验**：Electron 提供稳定的原生对话框、数据目录选择和进程管理。

## 3. 关键场景

### 场景 A：录入和导入台账

用户可直接新增记录，也可导入本系统导出的 XLSX。相同病理号允许出现多次；系统不进行病例合并。导入先展示创建/更新预览和错误，只有无错误时才能确认。

### 场景 B：编排实验编号

用户进入实验编排页面，从“待实验”中选择记录，填写 `20260801` 或任意前缀，调整临时队列顺序，得到 `20260801-1`、`20260801-2`。点击回写只更新实验编号；页面不保存编排单，状态和实验日期不变。实验结束后用户在台账手工标记“已完成”。

### 场景 C：手动与自动导出

手动导出打开 Windows“另存为”，适合临时改名、共享盘或按日期归档。自动导出只在配置时选择目录，此后按计划自动命名、重试并执行保留策略。两者的日期筛选均以台账实验日期为准。

### 场景 D：直接打印报告

用户维护 DOCX 模板及占位符映射，选择记录、打印机和 Office 引擎后直接打印。临时 DOCX 在打印完成后清理，产品不提供 DOCX/ZIP 下载入口。

### 场景 E：清理测试或历史记录

用户按当前项目的实验日期、创建日期或更新日期预览记录，确认精确数量后批量删除。锁定记录和预览后发生的集合变化都会阻止执行。

### 场景 F：选择业务数据位置

首次启动选择数据库目录；需要切换本地盘或共享盘时，在设置页选新目录并重启。应用不自动搬迁或删除旧目录，避免隐式数据损失。

## 4. MVP 功能

| 模块 | 功能 |
|---|---|
| 统计面板 | 项目/状态/月份统计，按台账实验日期筛选和导出 |
| 台账 | 独立 UUID CRUD、动态字段、状态、锁定、导入、导出、批删 |
| 实验编排 | 选择待实验记录、临时顺序编号、只回写编号、导出 |
| 报告 | DOCX 模板版本、占位符映射、Word/WPS 直接打印 |
| 自动导出 | 周期/Cron、目录、重试、历史和文件保留 |
| 审计 | 动作、实体 UUID、详情和时间搜索 |
| 设置 | 当前数据目录展示、选择并重启切换 |

明确删除：日期实验批次、重复实验入口、编排单持久化、编排日期回写、编排自动改状态、报告 DOCX/ZIP 下载、pywebview 壳和后端 tkinter 目录框。

## 5. 产品约束

- Windows 10+ 单用户桌面应用。
- 后端仅绑定 loopback。
- 报告打印依赖 Microsoft Word 或 WPS。
- 数据默认不离开用户选择的业务目录，自动导出可写用户配置的其他绝对目录。
- 面向用户的日期规则统一为 `Asia/Shanghai`。
- Element Plus 保留核心控件，Tailwind 只负责布局与视觉系统。
- Nuitka 与 PyInstaller 都在 GitHub Actions 验证，不在本地执行打包。
