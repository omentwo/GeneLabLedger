# 基因检测台账管理系统 — 需求文档

## 1. 范围与原则

本系统是 Windows 单用户桌面台账工具。Electron 管理桌面窗口、Python sidecar、原生文件对话框和数据目录；FastAPI/SQLite 管理业务数据；Vue 前端提供操作界面。

核心数据原则：

1. 每条台账记录由独立 UUID 标识。
2. 病理号是记录自身的普通字段，可重复；不得据此关联、合并或联动其他记录。
3. 实验编排只负责生成、排序、回写实验编号和导出 Excel。
4. 台账状态与实验日期由用户维护，编排不得修改。
5. 所有面向用户的当前日期与日期范围按 `Asia/Shanghai` 解释；时间戳以 UTC 存储。

## 2. 功能需求

### FR-1 检测项目与动态字段

- 项目支持新增、修改、删除、排序和“允许进入实验编排”开关。
- 每个项目独立定义文本、数字、日期和可编辑下拉字段。
- 核心字段为实验日期、病理号、实验编号、状态。
- 实验编号可以在台账界面直接修改；状态仅有“待实验”和“已完成”。

### FR-2 台账记录

- 新增、查看、编辑、锁定、删除记录，每次新增都产生新 UUID。
- 同项目和跨项目均允许相同病理号；修改病理号只影响当前 UUID。
- “分配到其他项目”创建新的独立 UUID，仅复制病理号，不建立长期关联。
- 锁定记录不可编辑、导入覆盖或删除。
- 状态由用户手工切换；系统不自动标记“已完成”。
- 支持按项目、病理号/字段关键词、状态、实验日期和报告状态筛选。
- 支持多选更新报告状态。
- 不提供重复实验功能。

### FR-3 实验编号编排

- 实验编排页面保留左右两栏，但不创建或保存编排单。
- 用户自由填写最多 80 字符的实验编号前缀；同一前缀可以重复使用。
- 只有状态为“待实验”且所属项目启用编排的记录出现在候选区。
- 选择记录后在页面内临时组成编号队列；同一记录在当前队列中只能出现一次。
- 条目顺序为 1、2、3……，显示编号 `{前缀}-{顺序}`，例如 `20260801-1`。
- 支持手动上移/下移和按病理号、项目排序。
- 点击“编排完成并回写编号”时，只更新所选 UUID 的 `experiment_number`。
- 回写不得修改 `experiment_date`、`status`、`locked`。
- 前缀可修改并再次回写；若生成编号已被编排外的其他记录占用，原子拒绝并说明冲突。
- 编排表可随时导出 XLSX。

### FR-4 手动与自动 Excel 导出

手动导出：

- 台账、实验编排和统计面板统一生成 XLSX。
- Electron 桌面版必须调用 Windows“另存为”，支持修改文件名、选择目录、取消和覆盖确认。
- 浏览器开发模式允许回退到浏览器下载；该回退不代表桌面生产行为。
- 台账/统计导出按台账的 `experiment_date` 过滤，不使用编排日期。
- 台账工作表包含隐藏的 `_record_id` 与 `_project_id`，供精确回导。

自动导出：

- 保留任务 CRUD、启停、预设周期、五段 Cron、手动触发、失败重试和运行历史。
- 用户通过 Electron 原生目录选择框设置输出目录。
- 任务运行时自动命名并由后端直接写文件，不弹出“另存为”。
- 按任务配置保留最近 N 个成功文件，只能清理任务输出目录内的本任务文件。

### FR-5 Excel 导入

- 接受有效 `.xlsx`，最大 20 MiB、每表最多 10,000 数据行、200 列。
- 必须先预览再提交；用户可选择工作表。
- 表头按当前项目字段显示名或字段 key 映射；未知或重复表头属于阻断错误。
- `_project_id` 存在时必须与当前项目一致。
- `_record_id` 命中当前项目记录时精确更新；有效但不存在的 UUID 可恢复创建；为空则生成新 UUID。
- 不得按病理号查找、合并或覆盖记录。
- 锁定记录、跨项目 UUID、重复 UUID、无效状态/日期、重复或外部占用的实验编号均阻断提交。
- 整批导入在单个事务中完成，并写审计日志。

### FR-6 按日期批量删除

- 当前项目下可按实验日期、创建日期或更新日期选择闭区间。
- 创建/更新时间的日期边界按 `Asia/Shanghai` 转换为 UTC 查询。
- 必须先返回总数、锁定数、精确 UUID 列表和最多 200 条样例。
- 一次最多 10,000 条。
- 执行时重新查询；集合与预览不完全相等即拒绝。
- 任何锁定记录都会阻止整批删除；成功时在一个事务中删除并审计。

### FR-7 报告模板与直接打印

- 按项目管理 DOCX 模板版本，提取正文、页眉和页脚中的 `{{占位符}}`。
- 占位符支持字段、固定值、上海当前日期、实验编号和留空映射。
- 用户选择记录、打印机和 Word/WPS 引擎后直接打印。
- 后端只在 `<数据目录>/temp/reports/print-*` 创建临时 DOCX，打印完成或失败后清理。
- 不提供单 DOCX、批量 DOCX 或 ZIP 下载接口。

### FR-8 数据目录与桌面生命周期

- Electron 首次启动必须选择业务数据目录，不静默使用 Downloads、安装目录或固定 LocalAppData 业务目录。
- 数据库、模板和临时文件位于用户选择目录。
- 设置页可保存新目录并重启切换；系统不自动迁移或删除原目录内容。
- Electron 单实例运行，启动随机 loopback 端口的 Python sidecar，窗口关闭时停止 sidecar。
- 渲染进程启用沙箱和上下文隔离，只能通过白名单 preload 调用原生能力。

### FR-9 UI 与审计

- Tailwind CSS 负责布局、间距和视觉微调；保留 Element Plus 的表格、表单、对话框、日期选择和通知。
- 不启用 Tailwind Preflight，避免破坏 Element Plus。
- 数据变更记录动作、实体 UUID、详情和 UTC 时间；界面按上海时区显示。
- 审计日志默认最多保留 100,000 条且保留 365 天；后端启动时自动清理过期和超额日志。

## 3. 非功能需求

- HTTP 只绑定 `127.0.0.1`；Electron 只允许本应用页面导航并校验 IPC 发送者。
- SQLite 启用外键与 WAL。
- XLSX ZIP/XML 解析限制上传体积、成员体积、总解压体积、行列数，不向文件系统解压。
- DOCX 打印在隔离进程中运行，超时或退出时清理。
- Windows 10+；报告打印依赖 Microsoft Word 或 WPS。
- 后端使用 pytest/Ruff，前端使用 Vitest/vue-tsc/Vite。
- Nuitka 和 PyInstaller 均只通过 GitHub Actions 构建验证，本地验证不执行打包。

## 4. 数据完整性

- 唯一约束：项目名称、项目内字段 key/system key、记录实验编号。
- 不对病理号建立唯一约束。
- 删除记录级联删除动态字段值；编号队列是页面临时状态，不需要清理。
- 报告模板版本历史保留；自动导出历史按任务保留策略处理文件。
